# Implementation Plan: SR Pipeline Logging and Audit System

This plan details the steps to implement a comprehensive logging and auditing system for the SR Pipeline, ensuring traceability, observability, and automated verification of pipeline execution.

## 1. Create `sr_pipeline/logging_utils.py`
This module will provide the core logging infrastructure.
- **Dependencies**: `logging`, `json`, `time`, `uuid`, `pathlib`, `contextvars`, `typing`.
- **Context Management**:
    - Define `SR_STAGE = contextvars.ContextVar("sr_stage", default=None)`
    - Implement `set_stage(name)` and `get_stage()`.
- **Components**:
    - `init_run_id()`: Generates `YYYYMMDD-HHMMSS-{short_uuid}`.
    - `EventWriter` class:
        - `__init__(file_path)`: Opens file for appending.
        - `append(event_dict)`: Adds `ts` (timestamp), `run_id`, and writes JSON line.
    - `setup_logging(output_dir, run_id)`:
        - Creates `output_dir/logs`.
        - Configures a standard Python `Logger` (file handler -> `pipeline.log`, stream handler -> console).
        - Initializes `EventWriter` -> `events.jsonl`.
        - Returns `(logger, event_writer)`.

## 2. Modify `sr_pipeline/tools.py`
Update `HTTPToolPort` to instrument tool calls.
- **Update `__init__`**: Accept optional `logger` and `event_writer`.
- **Update `call`**:
    - Capture `start_time`.
    - Compute `payload_bytes` (length of JSON encoded payload).
    - Execute request.
    - Capture `end_time` and compute `latency_ms`.
    - Compute `response_bytes`.
    - **Log Event**: Write `tool_call` event to `event_writer` with:
        - `stage`: from `get_stage()`
        - `tool`: tool name
        - `ok`: success status
        - `latency_ms`, `payload_bytes`, `response_bytes`
    - **Log Info**: `logger.info` summary of the call.

## 3. Modify `sr_pipeline/orchestrator.py`
Update `Orchestrator` to manage lifecycle events.
- **Update `__init__`**: Accept `logger` and `event_writer`.
- **Update `run` loop**:
    - **Pre-Stage**:
        - Call `set_stage(stage.name)`.
        - Write `stage_start` event.
        - `logger.info(f"Starting stage: {stage.name}")`.
    - **Post-Stage (Success)**:
        - Write `stage_end` event (`ok=True`).
    - **Post-Stage (Failure/Exception)**:
        - Write `exception` event (`error_type`, `error_msg`).
        - Write `stage_end` event (`ok=False`).
        - `logger.error` with traceback.

## 4. Modify `run_pipeline.py`
Wire the components together.
- Call `init_run_id()`.
- Call `setup_logging(out_dir, run_id)`.
- Pass `logger` and `event_writer` to `HTTPToolPort` and `Orchestrator`.

## 5. Create `audit_logs.py`
Implement the verification logic.
- **CLI**: `argparse` for `--output_dir`.
- **Parsing**: Read `outputs/logs/events.jsonl`.
- **Analysis**:
    - Track active stages (stack/flag).
    - Count events by `kind`.
    - Map `stage_name` -> `tool_call_count`.
    - Collect exceptions.
- **Validation Rules**:
    1.  **Stage Integrity**: Every `stage_start` must have a matching `stage_end`.
    2.  **Error Free**: No `exception` events allowed.
    3.  **Tool Usage**: Every executed stage must have `tool_call_count >= 1`.
    4.  **Artifacts**: `paper.md` must exist and be non-empty.
- **Scoring**: Implement 0-10 scale based on violations.
- **Output**: Print summary metrics and `audit_verdict=PASS/FAIL`.
- **Exit Code**: 0 for PASS, 1 for FAIL.

## Verification
1.  Start `tools_server/dummy_tool_server.py` in Terminal 1.
2.  Run `python run_pipeline.py` in Terminal 2.
3.  Run `python audit_logs.py --output_dir outputs`.
4.  Check `outputs/logs/` for `pipeline.log` and `events.jsonl`.
